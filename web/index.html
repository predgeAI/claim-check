The finding

The connection test skipped the guard the description promised

The signal path does call assertUrlIsPublic. The Test button in the credentials dialog did not: it called the raw fetch on a URL the operator types, and reported the HTTP status back — a probe of any host the operator can name, including private ranges.

Against the reviewer

The human pass was thorough, and partial

The maintainer’s final review names four conclusions under “Does it match the description”. Those four cover 14 of the 29 claims, and the tool agrees with him on all 14. He did not address the other 15 one by one — and the failing claim is among them.

Where it breaks

Two limits we found by trying to break our own tool

false holds

A cheaper verifier missed the same bug

To save budget, one build of the live executor ran each subagent on the diff alone. It returned holds for c02: it found the guarded path, and stopped.

“Every request is guarded” is a universal claim. One example cannot confirm it; only a counterexample can refute it. Universal claims now get a different instruction: search every call site, list what was checked, and answer cannot tell if coverage isn’t proven. With that rule the live run finds the bug again.

out of reach

It only checks what someone claimed

The worst defect we know of in this codebase is a mismatch between two canonicalisation functions: the signer drops undefined keys, the verifier does not. Identical bytes today; incompatible the day a field becomes optional.

No sentence in the PR says anything about it, so no claim was extracted and no subagent looked. That is a boundary of the method, not a bug in Bob — and it is the same reason four rounds of review walked past it.
